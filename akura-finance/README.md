# Akura Finance

MFE React/Ant Design/Vite dengan Module Federation di port **4176**. Expose: `akuraFinance/FinanceApp`.

## Menjalankan

```powershell
cd akura-finance
npm ci
npm run dev
```

Jalankan shell pada port 4173. Port 4176 mengarahkan browser ke `/finance` pada shell. Konfigurasi opsional tersedia di `.env.example`. Shell memakai `AKURA_FINANCE_REMOTE_URL` (default `http://localhost:4176/remoteEntry.js`). Restart shell setelah perubahan konfigurasi federation/environment.

## Menu

Sidebar dan route shell mengikuti API `my-menus`. Buat menu induk `finance`, label `Finance`, `hasItem: true` melalui App Manager, beserta item dan Menu Access sesuai role/section:

| Item key | Label | URL |
| --- | --- | --- |
| `finance_quotations` | Quotation | `/finance/finance_quotations` |
| `proforma_invoices` | Proforma Invoice | `/finance/proforma_invoices` |
| `invoices` | Invoice | `/finance/invoices` |

Key `finance_quotations` sengaja berbeda dari Marketing karena menu item key unik secara global. Alias `/finance/quotations`, `/finance/proforma-invoice`, dan `/finance/invoice` didukung. Route create/edit Quotation tidak tersedia. Implementasi frontend ini tidak mengubah data menu atau permission backend.

## Status API

- Contract verified against local Swagger at `http://localhost:5000/api-docs.json`.
- Quotations use branch-scoped, read-only `/marketing/quotation-references` and `/marketing/quotation-references/{quotationId}`. The reference list is capped at 1000 active approved quotations and paginated locally; Finance does not mutate Marketing quotations.
- Invoice and Proforma Invoice share `/finance/documents` for list/create and `/finance/documents/{id}` for get/update/delete, with `/history` for audit history. Lists send `kind=INVOICE` or `kind=PROFORMA_INVOICE`; creation includes the corresponding `kind` in the body.
- Swagger `FinanceDocumentCreate` requires `kind`, `companyId`, `title`, `purchaseOrderNumber` (1-100 characters), `purchaseOrderDate` (calendar date), and `items` (1-100 unique item size UUID strings). Optional fields are `location`, `dueDate` and `notes`. Finance resolves company catalog prices on the server. Each item represents one inspection unit and one maintenance unit when available. The client sends no source, quotation snapshot, price, quantity, discount, tax, total, actor or branch override.
- The creation modal follows the quotation form: responsive two-column document fields, a searchable company selector and a paginated item picker with service, item, size and company price estimates. Company search uses `GET /marketing/companies`; item selection uses `GET /marketing/items/sizes/prices` with `companyId`, filters, pagination and exclusions as documented in local Swagger. These read-only Marketing options require the corresponding API access; lookup failures show a retry action. Changing company clears selected items and their price estimates. Only selected UUID strings are submitted to Finance. Document details show the immutable purchase order number/date. Finance quotation references are view only; quotation-based creation remains in Marketing through its documented endpoint.
- Both document numbers and dates are generated by the server. The client validates deadlines against the Jakarta calendar date. PATCH sends only changed title, dueDate or notes with the current version; quotation deadlines cannot be cleared.
- Invoice and Proforma Invoice headers show only the Add action. Lists reload automatically after document changes and when pagination or filters change.
- Document lists and history follow Marketing's request sequence guard: cleanup ignores stale responses without aborting HTTP requests. Only the latest request can update data, loading, errors or pagination. The same guards apply to the unified document collection.
- DRAFT approval uses `POST /finance/documents/{id}/approve` with `version`, producing ON_PROGRESS. Only ON_PROGRESS documents can be finalized through PATCH to FINAL. Conflicts require reloading; mutation submits are locked while pending.
- Details display document `items`, including DIRECT documents, company snapshot, location and server-calculated tax/totals. Historical quotation items remain a fallback for legacy documents.
- Marketing's create action remains `POST /marketing/quotations/{quotationId}/invoices` with quotationId, kind, dueDate and location. Its current Swagger contract is unchanged; it remains exclusive to MARKETING and checks quotation/Work Order eligibility.

## Verification

From the workspace root:

```powershell
node --test tests/marketing-invoice.test.mjs tests/finance-contract.test.mjs
node --test tests/finance-document-loading.test.mjs tests/finance-document-options.test.mjs
```

The Finance contract test reads local Swagger and mocks document requests; it does not create backend records. Run lint on changed files and `npm run build` in the affected MFE directories.
